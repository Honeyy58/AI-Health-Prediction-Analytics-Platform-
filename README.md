## Overview & Architecture

The platform follows a layered client-server architecture with separation of concerns:

```
React Frontend (Vite + Tailwind + Recharts)
       │
       │ REST API / JSON (Axios)
       ▼
FastAPI Backend (Uvicorn + Pydantic)
       │
       ├──────────────► ML Service (Singleton in-memory)
       │                 ├── StandardScaler (scaler.pkl)
       │                 └── Logistic Regression (diabetes_model.pkl)
       │
       └──────────────► MySQL Database (health_prediction)
                         └── predictions table (Indexed: id, created_at, prediction)
```

### Prediction Flow:
1. **User input**: Patient enters demographic, lifestyle, and clinical biomarker data.
2. **Client validation**: Real-time bounds validation ensures values are within valid clinical intervals.
3. **API submission**: Payload sent via `POST /predict`.
4. **Pydantic validation**: Strict typing and range verification at the API layer.
5. **Preprocessing**: Normalizes categoricals and scales continuous inputs via the fitted `StandardScaler` matching training feature order.
6. **Inference**: Logistic Regression generates classification (0 or 1) and calibrated confidence probability.
7. **Persistence**: Saves assessment record, confidence, and timestamp into MySQL.
8. **UI Presentation**: Displays an interactive result gauge, biomarker summary, and non-diagnostic guidance.
9. **Real-time Analytics**: Aggregates cohort trends and demographic charts on the dashboard.

## Key Features

- **Logistic Regression Engine**: Trained on 8 key clinical indicators with balanced class weighting, achieving **94.5% Accuracy** and **0.976 ROC-AUC**.
- **Exact Feature Order Preservation**: Guarantees identical feature alignment between offline training and online inference.
- **Multi-Section Assessment Form**: Clean 4-part form (Personal, Medical History, Lifestyle, Clinical Biomarkers) with one-click test presets.
- **Dynamic Result Gauge**: Animated circular confidence gauge with semantic color grading (Emerald for lower risk, Rose for higher risk).
- **Population Analytics Dashboard**: 7 KPI stat cards and 4 Recharts visualizations (Time series area chart, Donut distribution, Age demographic breakdown, Biomarker scatter plot).
- **Prediction History & Audit Log**: Searchable, filterable, sortable, and paginated table with individual record detail modals and delete confirmation.
- **Dark / Light Mode**: Seamless theme toggle with system preference detection and `localStorage` persistence.
- **Resilient Error Handling**: Clean HTTP status codes and user-friendly error messages with zero raw stack traces exposed.

## Machine Learning Workflow

The model is trained on standard epidemiological distributions (ADA / CDC benchmarks) incorporating 8 target features:

1. `gender`: Categorical (`Female`: 0, `Male`: 1, `Other`: 2)
2. `age`: Continuous (1 to 120 years)
3. `hypertension`: Binary (`No`: 0, `Yes`: 1)
4. `heart_disease`: Binary (`No`: 0, `Yes`: 1)
5. `smoking_history`: Categorical (`never`: 0, `No Info`: 1, `current`: 2, `former`: 3, `ever`: 4, `not current`: 5)
6. `bmi`: Continuous (10.0 to 80.0 kg/m²)
7. `HbA1c_level`: Continuous (3.0% to 20.0%)
8. `blood_glucose_level`: Continuous (40 to 600 mg/dL)

### Model Performance:
- **Accuracy**: 94.50%
- **Recall**: 92.49%
- **ROC-AUC**: 0.9762
- **Coefficients (Top Risk Influencers)**:
  - `HbA1c_level`: +1.39
  - `blood_glucose_level`: +1.13
  - `bmi`: +0.46
  - `age`: +0.43

## Database Schema

Database: `health_prediction`

```sql
CREATE DATABASE IF NOT EXISTS health_prediction;
USE health_prediction;

CREATE TABLE IF NOT EXISTS predictions (
    id INT PRIMARY KEY AUTO_INCREMENT,
    gender VARCHAR(20) NOT NULL,
    age FLOAT NOT NULL,
    hypertension BOOLEAN NOT NULL,
    heart_disease BOOLEAN NOT NULL,
    smoking_history VARCHAR(50) NOT NULL,
    bmi FLOAT NOT NULL,
    hba1c_level FLOAT NOT NULL,
    blood_glucose_level FLOAT NOT NULL,
    prediction VARCHAR(20) NOT NULL,
    confidence FLOAT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_created_at (created_at),
    INDEX idx_prediction (prediction)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

## REST API Reference

Interactive Swagger documentation is available at `http://localhost:8000/docs` and ReDoc at `http://localhost:8000/redoc`.

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `GET` | `/` | API metadata, health status, and ML loading state |
| `GET` | `/health` | System health check (ML engine & database) |
| `POST` | `/predict` | Evaluates patient data, stores record in MySQL, returns prediction |
| `GET` | `/predictions` | Paginated prediction history with search, filter, and sorting |
| `GET` | `/predictions/{id}` | Detailed assessment record by ID |
| `DELETE` | `/predictions/{id}` | Permanently deletes a prediction record |
| `GET` | `/analytics` | Dashboard analytics KPIs and chart dataset aggregations |

### Sample Prediction Request:
```json
POST /predict
{
  "gender": "Female",
  "age": 52.0,
  "hypertension": 0,
  "heart_disease": 0,
  "smoking_history": "never",
  "bmi": 28.5,
  "HbA1c_level": 6.2,
  "blood_glucose_level": 160.0
}
```

### Sample Prediction Response:
```json
{
  "prediction": 1,
  "result": "Positive",
  "confidence": 92.44,
  "message": "The model predicts a higher likelihood of diabetes.",
  "prediction_id": 1,
  "created_at": "2026-09-24T02:00:00"
}
```

## Installation & Setup

### 1. Prerequisites
- Python 3.9 or higher
- Node.js 18+ and npm
- MySQL Server 8.0+

---

### 2. Database Setup (MySQL)

1. Make sure MySQL service is running:
   ```bash
   # On macOS (Homebrew):
   brew services start mysql

   # On Linux:
   sudo systemctl start mysql
   ```

2. Create the database and tables using the provided schema:
   ```bash
   mysql -u root -p < database/schema.sql
   ```
   *(Alternatively, run `python backend/init_db.py` after configuring your `.env`)*

---

### 3. Backend Setup (FastAPI)

1. Navigate to the backend or root folder:
   ```bash
   python3 -m venv venv

   # Activate virtual environment
   # On macOS/Linux:
   source venv/bin/activate
   # On Windows:
   venv\Scripts\activate
   ```

2. Install dependencies:
   ```bash
   pip install -r backend/requirements.txt
   ```

3. Configure environment variables in `backend/.env`:
   ```bash
   cp backend/.env.example backend/.env
   ```
   Edit `backend/.env` with your MySQL credentials:
   ```ini
   DB_HOST=localhost
   DB_PORT=3306
   DB_USER=root
   DB_PASSWORD=your_mysql_password
   DB_NAME=health_prediction
   ```

4. Run the FastAPI server:
   ```bash
   python -m uvicorn backend.app.main:app --reload --port 8000
   ```
   The backend will be accessible at: `http://localhost:8000`  
   Interactive API Docs: `http://localhost:8000/docs`

---

### 4. Frontend Setup (React + Vite)

1. In a new terminal window:
   ```bash
   cd frontend
   npm install
   ```

2. Start the development server:
   ```bash
   npm run dev
   ```
   The web application will open at: `http://localhost:5173`

---

### 5. Model Training (Optional)

Trained artifacts (`diabetes_model.pkl` and `scaler.pkl`) are pre-built and saved in `backend/ml/`. If you wish to retrain the model or regenerate the dataset:

```bash
python ml/train.py
```
This script will:
- Generate a 25,000-sample balanced dataset in `ml/dataset/diabetes_prediction_dataset.csv`
- Train a `LogisticRegression` model with balanced class weights
- Evaluate accuracy, recall, precision, and ROC-AUC
- Export `diabetes_model.pkl`, `scaler.pkl`, and `metadata.json` to both `ml/` and `backend/ml/`
